## 2. Smoke Suite (must pass before any commit lands)

### 2.1 Project Initialization
| ID | Scenario | Expected |
|----|----------|----------|
| SM-01 | `/sk.init` in empty dir | `.skspec/` created with all canonical subdirs and stub state files |
| SM-02 | `/sk.init` rerun in existing `.skspec/` | Detects existing structure; offers repair-only mode; does not clobber files |
| SM-03 | `/sk.init` in non-empty repo with code | Adds `.skspec/` alongside without touching existing files |

### 2.2 SDD Document Flow
| ID | Scenario | Expected |
|----|----------|----------|
| SM-10 | `/sk.specify` with no active iteration | Writes `prd/spec-001.md`; updates `.iterations.json` with active=001 |
| SM-11 | `/sk.specify` with active iteration | Writes proposal to `.prd-pending/proposal-<ts>.md`; sets `state.json.paused=true, pause_reason=prd_proposal` |
| SM-12 | `/sk.specify --accept <proposal>` | Merges into `prd/spec-001.md`; archives proposal; clears pause; logs to `decision-log.md` |
| SM-13 | `/sk.specify --reject <proposal>` | Archives proposal as rejected; clears pause; logs |
| SM-14 | `/sk.plan` without `spec-00N.md` | Refuses with explicit error pointing to `/sk.specify` |
| SM-15 | `/sk.tasks` without `plan-00N.md` | Refuses; explicit error |

### 2.3 Master Loop
| ID | Scenario | Expected |
|----|----------|----------|
| SM-20 | `/sk.go` end-to-end on a trivial 3-task iteration | All 5 phases execute; iteration ends as `completed`; retro file written |
| SM-21 | DAG with parallelizable tasks (e.g., T-02 and T-03 both depend only on T-01) | After T-01, decision-log shows T-02 and T-03 dispatched in same batch |
| SM-22 | `/sk.go` with `max_concurrency=1` | Tasks dispatched strictly serially even when DAG allows parallel |
| SM-23 | `/sk.step` | Exactly one batch dispatched, then pause; status shows `paused: true, pause_reason: user` (or `step`) |
| SM-24 | `/sk.review` | Multi-role review subagents fire; no task dispatched; decision-log entry written |

### 2.4 Pause / Resume
| ID | Scenario | Expected |
|----|----------|----------|
| SM-30 | `/sk.pause` mid-batch | Current batch finishes; pause takes effect afterwards; state.json reflects |
| SM-31 | `/sk.resume` after `/sk.pause` | Loop continues from Step 0; no duplicate work; no skipped tasks |
| SM-32 | Kill Claude Code mid-batch (simulate crash); restart; `/sk.resume` | State recovered from snapshot; tasks marked `running` get re-evaluated as failed-or-resumed per validator |
| SM-33 | `/sk.pause` while already paused | Idempotent; no-op with informative message |

### 2.5 Failure & Recovery
| ID | Scenario | Expected |
|----|----------|----------|
| SM-40 | Task fails once | retry_count=1; next loop re-dispatches |
| SM-41 | Task fails `max_retries+1` times | state=`failed`; loop pauses with `pause_reason=max_retries_exceeded`; user-action prompt logged |
| SM-42 | `/sk.tasks.retry <id>` on failed task | retry_count reset; state→pending; loop resumes if not paused |
| SM-43 | Deadlock: 2 consecutive loops with empty `ready_set` and non-empty `pending` | Pause with `pause_reason=deadlock`; decision-log entry |

### 2.6 Agent Roster Reconciliation
| ID | Scenario | Expected |
|----|----------|----------|
| SM-50 | ERD introduces "PostgreSQL schema migration" wording | `database-reviewer` added to roster within next loop; rationale recorded |
| SM-51 | All security-related tasks complete and roster has `security-reviewer` | After 2 loops with no security tasks, role marked `inactive` |
| SM-52 | `/sk.agent.add custom-role --type general-purpose` | Manually appended; survives next reconciliation (TPM treats manual entries as advisory unless explicitly contradicted) |
| SM-53 | `max_active_agents=8`; reconciliation tries to add 9th | TPM deactivates lowest-priority before adding new; logs the swap |

### 2.7 PRD Reverse-Proposal
| ID | Scenario | Expected |
|----|----------|----------|
| SM-60 | Subagent finds spec contradiction during task execution | Writes `.prd-pending/proposal-<ts>.md` with structured fields; loop pauses |
| SM-61 | User runs `/sk.specify --accept <id>` | Spec updated; ERD review re-runs (Phase 1 partial); loop resumes |
| SM-62 | User runs `/sk.specify --reject <id>` | Proposal archived to `.prd-pending/rejected/`; loop resumes; subagent must work around or fail |
| SM-63 | Two proposals filed in same batch | Both queued; user prompted to accept/reject one at a time |

### 2.8 Iteration Lifecycle
| ID | Scenario | Expected |
|----|----------|----------|
| SM-70 | `/sk.iteration.complete` after all tasks done | Retro subagents fire; `.knowledge/retrospectives/001-retro.md` written; `.iterations.json` updated |
| SM-71 | `/sk.specify` after iteration 001 completed | Drafts `spec-002.md`; iteration 002 becomes active |
| SM-72 | Iteration 002 has access to `.knowledge/` from iteration 001 | Architect subagent prompt includes knowledge excerpts; verifiable in subagent's output reasoning |
| SM-73 | `/sk.iteration.complete` with pending tasks | Refuses; lists what's blocking |

### 2.9 Headless Mode
| ID | Scenario | Expected |
|----|----------|----------|
| SM-80 | `claude -p '/sk.go --until-pause'` runs to iteration completion | Exit code 0; iteration completed; final status printed |
| SM-81 | Headless mode hits PRD proposal | With `--no-confirm`: proposal auto-rejected, logged; loop continues. Without: exits non-zero |
| SM-82 | Headless mode hits max_retries | Exits non-zero; decision-log explains |

## 4. Integrity & Edge Cases

### 4.1 Filesystem Hand-Edits (user editing during pause)
| ID | Scenario | Expected |
|----|----------|----------|
| INT-01 | User edits `prd/spec-001.md` while paused | TPM next loop reads new content; if material change, may emit ERD review |
| INT-02 | User edits `.task/tasks-001.md` directly | TPM resyncs sidecar JSONs on next loop; logs the discrepancy |
| INT-03 | User deletes a snapshot file | TPM tolerates; affected task's restore path unavailable; logged |

### 4.2 Concurrency Bounds
| ID | Scenario | Expected |
|----|----------|----------|
| INT-10 | `max_concurrency=10` but ready_set has 3 | Dispatches 3 (no padding) |
| INT-11 | Single non-idempotent task fails on retry | Auto-restore from snapshot if available; else escalate |

### 4.3 Schema Versioning
| ID | Scenario | Expected |
|----|----------|----------|
| INT-20 | `.skspec/.version` mismatch with sk binary expected version | Warn on first command; refuse `/sk.go` until `/sk.lint --migrate` (v2) or manual fix |
