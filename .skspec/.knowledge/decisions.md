# Architectural Decisions

Cross-iteration architectural decisions with rationale. Each entry: title, status, context, decision, consequences, source.

## sk registers as Claude Code agent skill, not flat command file

- **Status**: ratified 2026-04-20 (iteration 001, loop 0, via T-01 PRD-proposal-turned-ERD-revision).
- **Context**: Iteration 001's ERD v0.1 (§3, §4) assumed Claude Code picks up Harness slash commands from flat files at `.claude/commands/sk.<name>.md` with `name`, `allowed-tools`, `argument-hint` frontmatter, and that user invocations would be `/sk.init`, `/sk.specify`, etc. (dot-delimited). T-01 forked spec-kit and validated against upstream SHA `c118c1c30f961921e41891df3318a2ccd2ceea54`; the actual `ClaudeIntegration` class in `speckit/specify_cli/integrations/claude/__init__.py` (lines 41–54) registers via `commands_subdir="skills"`, writes `.claude/skills/<dir>/SKILL.md` per the `agentskills.io` spec, uses hyphenated user invocations (`/speckit-plan`), and honors `$ARGUMENTS` but not `allowed-tools` in the frontmatter.
- **Decision**: adopt the Claude Code agent-skills layout for all Harness commands. Outputs live at `.claude/skills/sk-<name>/SKILL.md` (directory + SKILL.md). User-facing invocation is `/sk-<name>` (hyphenated, no dot). Frontmatter follows the upstream `CommandRegistrar.build_skill_frontmatter` shape (`name`, `description`, `compatibility`, `metadata.{author,source}`) plus Claude-specific post-processed flags (`argument-hint`, `user-invocable`, `disable-model-invocation`). Drop `allowed-tools` entirely. Keep `$ARGUMENTS`. Preserve internal dot-delimited names (`sk.init`, `sk.tasks.retry`) in task IDs, decision-log `actor=` values, state-JSON keys, and all programmatic references — the dot-to-hyphen conversion happens only at the adapter boundary (`sk_harness.speckit_adapter`).
- **Consequences**:
  1. The adapter layer (ERD §1.3) grows from "path rewrite" to "path rewrite + frontmatter translation." `inherit_body()` must strip upstream frontmatter (dropping `handoffs:` and `scripts:` keys), emit Harness `agentskills.io`-compliant frontmatter, and rewrite `/speckit-<x>` body references to `/sk-<x>`. T-11 complexity rises from S/M → M/L.
  2. Any future Claude-adjacent integration (or any new agent-runtime target) must first check its registration mode — skills-mode vs. flat-commands-mode is a per-integration design switch, not a Claude Code universal. The ERD validation step (§T-01 pattern) is now mandatory for any integration-touching iteration.
  3. Iteration 002+ inherits this rule directly: the architect subagent reads `.knowledge/decisions.md` at Phase 1 Step 0, so the "skills-not-commands" layout does not need to be re-derived from upstream source.
- **Source**: T-01 evidence in `docs/ERD-VALIDATION.md` rows 11–13, 16, 20. PRD proposal: `.skspec/.prd-pending/accepted-as-erd-revision-20260420T050821Z.md`. ERD revision: `.skspec/.erd/plan-001.md` v0.2 §1.3, §3, §4, §18 OQ-3, §19 Wave 4/5 notes.
