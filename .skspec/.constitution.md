# sk Harness Constitution

Project principles. These override any command-level convenience and are the lens through which every decision is reviewed.

## I. SDD First, Harness Second

The Spec → Plan → Tasks → Implement discipline from spec-kit is the substrate. sk adds a Harness layer on top (state, scheduling, multi-agent, knowledge) but must never undermine the SDD contract: no implementation without a plan, no plan without a spec, no spec without user approval.

## II. Single Source of Truth by Ownership

Every artifact has exactly one writer.
- **User owns** `prd/`, `tests/`, `docs/`, `references/` — the requirement and environment authority.
- **Agent owns** everything under `.*` (dot-prefixed) — derivations, state, knowledge, roster.
- Agent proposals to change user-owned files go through `.prd-pending/` and require explicit user acceptance.

## III. Reversibility

Before any destructive action (task execution that mutates code, ERD rewrite that supersedes prior design), a snapshot is written. `sk` never deletes; it archives, marks inactive, or versions.

## IV. Observability Is Non-Optional

Every TPM decision, agent roster change, review outcome, and task state transition is appended to `.progress/decision-log.md`. A user who opens the project a week later must be able to read the log and understand what the agent did and why.

## V. Graceful Degradation

On failure, the default is to **pause cleanly at task boundaries**, not to crash or fire retries indefinitely. Max retries is bounded. Deadlocks are detected (≥ 2 loops with empty ready-set) and escalated to the user.

## VI. Fork, Don't Rewrite

sk is a fork of spec-kit with additions, not a rewrite. Upstream speckit templates, commands, and scripts are preserved with surface-level renames (`speckit.*` → `sk.*`) and additive Harness commands. Merging upstream improvements must remain feasible.

## VII. Human in the Loop for Intent, Agent in the Loop for Execution

PRD changes require user confirmation. Everything else — ERD drafts, task decomposition, agent roster, knowledge extraction, retry strategy, architectural refactors in response to review — is agent-autonomous but fully logged.

## VIII. Iteration Independence

Each iteration ships its own `spec-00N.md` / `plan-00N.md` / `tasks-00N.md` / `test-plan-00N.md`. No cross-iteration merging; later iterations reference earlier ones as context only. The accumulated state is the codebase itself plus `.knowledge/`.

## IX. Concurrency Is Batched, Not Streamed

Parallelism is within a task batch (DAG-ready tasks dispatched together via Task tool); it is not a streaming scheduler. Between batches, TPM re-evaluates the plan. This keeps state transitions atomic and debuggable.

## X. Self-Hosted Development

sk is developed using sk. Iteration 001 (this one) is the bootstrap: the PRD, plan, and tasks for building sk are themselves managed inside `.skspec/`. If the process is painful for its own authors, the process is wrong.
