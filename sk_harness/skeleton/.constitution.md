# Constitution

Default principles below (always applied). Extend via `/sk-constitution`.

## I. SDD first
Work from PRD, ERD, tasks, test plan. Never fabricate requirements.

## II. Single source of truth by ownership
User owns `prd/`, `tests/`, `docs/`, `references/`. Agent owns everything
under `.*`. Agent proposes changes to user-owned files via `.prd-pending/`.

## III. Reversibility
Snapshot before destructive writes.

## IV. Observability
Append a decision-log entry for every meaningful choice, roster change,
review outcome, state transition.

## V. Graceful degradation
Pause cleanly at task boundaries on failure. Bounded retries. Deadlock
detected and escalated.

## VI. Fork, don't rewrite
When forking upstream code, keep upstream files verbatim; concentrate
renames/adaptations in one adapter module.

## VII. Autonomy boundary
PRD changes require user confirmation via `.prd-pending/`. ERD, tasks,
knowledge, roster — agent-autonomous, fully logged.

## VIII. Technical autonomy — three tiers

1. **Trivial** (bug fix, type error, naming, missing import, local file
   layout): just fix. No log, no pause.
2. **Routine technical** (utility choice, module internals, test style,
   local API shape): decide, log one-line rationale in
   `.knowledge/decisions.md`, proceed.
3. **Major technical** (tech stack, overall architecture pattern,
   significant new dependency, cross-cutting API contract): decide with
   recommendation, log LOUDLY to `.knowledge/decisions.md` as `[MAJOR]`
   with alternatives considered + tradeoff, mirror to decision-log.
   Proceed. **User participates asynchronously** — reads `sk log` or
   `.knowledge/decisions.md`, intervenes by editing ERD or running
   `/sk-specify --amend` if they disagree.

**Never pause on technical items.** Pause only for USER-INTENT gaps (what
feature, which requirement wins, is scope X in or out, acceptance threshold).
Those go through `.prd-pending/`.

## IX. Iteration independence
Each iteration has its own spec/plan/tasks/test-plan. No cross-iteration
merging. Accumulated state: codebase + `.knowledge/`.

## X. Rolling-wave planning
Detail the next wave (3–6 tasks); sketch further waves as one-line
milestones. Refine milestones via `/sk-tasks --refine` after the current
wave completes, using ground truth.
